## 一句话结论

把「AI 个人档案」放进 GitHub，就能做到换 AI、换电脑都不丢上下文——因为它同时是**可被 agent 直读直改的文本仓库**、**可回退的版本历史**、**不绑定任何厂商的长期资产**。

## 核心结构（视频的三段式）

1. **为什么要建**：每换一个 AI 工具或一台电脑，你就得从头解释自己；agent 不懂你，产出就永远是"通用答案"。
2. **为什么选 GitHub**：
   - agent 可以直接读、直接改（纯文本 + API）；
   - 每次修改都有 commit，可一键回退——防误删多年积累；
   - 资产不在任何一家 AI 厂商手里，换工具零迁移成本。
3. **怎么建**：用一段提示词让 agent 生成档案骨架（身份、偏好、工作流、项目、决策记录），推到 GitHub 私有仓库即可。

## 我的核对

- 观点成立，但"AI 直接改仓库"需要给 agent 一个 **有写权限的 git token**，等于把仓库钥匙交出去，建议用细粒度 token + 只给单个仓库。
- 视频结尾"评论区打『AI个人档案』"是引流话术，不影响方法本身。
